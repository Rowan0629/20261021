# 設計：聊天室指令上線／下線（待命／運作兩種狀態）

日期：2026-10-26　狀態：待使用者審閱

## 1. 背景與目標

現在 bot 要靠一個開著的視窗才存在：開機後會跳出視窗並自動上線，視窗關掉或當掉 bot 就下線。

目標：

- 開機後**不跳出視窗**，也**不自動開始處理照片**。
- 由**伺服器管理員**在聊天室打指令，才讓 bot 上線處理照片；也可以打指令讓它下線。

成功標準：

1. 開機後沒有任何視窗，bot 在背景待命，Discord 顯示「閒置」。
2. 管理員在指定頻道打 `!上線`，bot 開始處理照片並回覆「已上線」。
3. 管理員打 `!下線`，bot 做完手上的工作後回到待命。
4. 待命期間傳的照片不處理、不補處理。
5. 四段防護與 `.env` 的四個變數都不變。

## 2. 前提與取捨

完全下線的 bot 聽不到任何指令，所以必須有一個程式常駐聽。已與使用者確認：可以背景待命。

選用 **A 做法：同一支 bot 常駐，分「待命」「運作」兩種狀態**。
不選 B（另寫待命程式再啟動／關閉真正的 bot）：兩者待命開銷差不多，B 要多管一支程式和兩條 Discord 連線的交接，容易出錯。

## 3. 行為

| 狀態 | Discord 顯示 | 行為 |
|---|---|---|
| 待命（開機後的預設） | 閒置，狀態文字「待命中，管理員輸入 !上線」 | 只聽 `!上線`；照片、回覆、@bot 一律忽略；不跑 `pending/` 補寫與 `awaiting/` 逾時檢查 |
| 運作 | 線上 | 與現在完全相同 |

指令（只在 `CHANNEL_ID` 指定的頻道有效，內容須完全等於指令，不經 AI）：

- `!上線`：待命 → 運作。回覆「已上線」，並接續處理 `pending/`、`awaiting/` 裡未完成的資料（與目前啟動時相同）。已在運作時回覆「已經在運作中」。
- `!下線`：運作 → 待命。不再接收新工作；手上和已在佇列中的工作做完，再回覆「已下線」。已在待命時回覆「目前就是待命中」。
- 非管理員打指令：只回「只有伺服器管理員可以上線／下線」，狀態不變。
- 待命期間，`!下線` 以外的內容，包含照片，都靜默忽略（不回任何話，避免洗版）。
- 下線等待期間（`!下線` 之後、佇列清空之前）：不收新照片；再打 `!上線` 會取消下線並回到運作。

管理員判斷：發話者在該伺服器有「管理伺服器」（`manage_guild`）權限；伺服器擁有者自動符合。不新增 `.env` 變數。

## 4. 程式改動

- `bot.py`：新增狀態（待命／運作／下線中）。`on_message` 分流最前面加指令判斷，其後依狀態決定是否進入原有分流。worker 與 `pending/`、`awaiting/` 的背景工作改為「進入運作」時才啟動／接續，「回到待命」時停止收新工作。更新 presence。
- `replies.py`：新增上述五句回覆文字。
- `__main__.py`：不改流程；`bot.run()` 之後的行為由 `bot.py` 的狀態管理。
- 四段防護：不動。`claude_client.py`、`photos.py`、`store.py` 不碰。

細節（命名、worker 如何暫停）在實作計畫中決定，原則是沿用現有 `bot.py` 的結構，並保持 `handlers.py` 不碰 Discord。

## 5. 開機啟動

- 新增 `start_bot_hidden.vbs`：用隱藏視窗（style 0）呼叫 `啟動bot.bat`。放進 `shell:startup` 後，開機不再跳視窗。檔名與內容刻意只用英文：Windows 以系統 ANSI 編碼讀 `.vbs`，中文會亂碼，所以它是靠檔名結尾 `bot.bat` 找到啟動檔。
- `啟動bot.bat`：保留目前已修改（意外當掉會自動重開）的版本，新增「隱藏模式」參數：隱藏模式下訊息與錯誤改寫進 `data\startup.log`（設定錯誤發生在 `bot.log` 建立之前，所以另外記；超過約 1 MB 就刪掉重寫），設定錯誤時不停在 `pause`，避免卡在看不見的視窗。重開前的等待改用 `ping`（隱藏時 `timeout` 會立刻失敗，變成無間隔重開）。
- 使用者目前放在 `shell:startup` 的舊捷徑需自行刪除；實作完成後會給步驟，不替使用者操作。
- 手動雙擊 `啟動bot.bat` 仍可用（有視窗），同樣從待命開始。

## 6. 測試

沿用現有風格（假的訊息物件，不連 Discord），先寫測試：

- 待命時：照片被忽略、`pending/` 補寫不執行。
- 管理員 `!上線` → 進入運作並回覆；非管理員被擋。
- 非 `CHANNEL_ID` 頻道的指令被忽略。
- `!下線`：現有工作做完才回「已下線」；下線等待期間的新照片被忽略。
- 重複 `!上線`、重複 `!下線`、下線等待期間 `!上線` 的行為。
- 既有 292 個測試維持通過；`uv run python tools/guard_lines.py` 回報四段防護成對、全部開啟。

自動測試無法涵蓋真正的 Discord 與開機啟動，這兩項需使用者實測（見 §8）。

## 8. 使用者實測項目（⚠️ 需要真實環境）

- [ ] 重新開機：沒有視窗，Discord 上 bot 顯示閒置。
- [ ] 待命中傳照片：沒有任何反應。
- [ ] 管理員 `!上線` → 綠燈，「已上線」；傳照片可正常歸檔。
- [ ] 非管理員 `!上線` → 被拒絕，狀態不變。
- [ ] 處理中打 `!下線` → 手上的做完才「已下線」，回到閒置。
- [ ] 用假設定（例如暫時改壞 `.env`）隱藏模式啟動：不卡死，原因寫在 `data\startup.log`（✅ 已用錯誤的 `CHANNEL_ID` 驗證過）。

## 9. 刻意不做

- 完全關閉程序的指令（要徹底停止用工作管理員結束 Python）。
- 定時自動上線／下線。
- 補處理待命期間傳的照片（與原需求「關著不處理」一致）。
- slash command（需另外註冊，純文字指令已足夠）。
